下面是一份面向 **Agent 工具开发者/维护者** 的排查报告。目标不是解释 Git，而是帮助定位：

> **为什么 OpenSeek Agent 的 Windows sandbox 中执行 Git for Windows 命令会 timeout，以及如何验证、修复。**

---

# Windows Sandbox 中 Git for Windows 执行 Timeout 问题排查报告

## 0. 问题摘要

### 现象

在 OpenSeek Agent 的 Windows sandbox 环境中：

执行：

```powershell
git --version
```

或：

```powershell
D:\Git\mingw64\bin\git.exe version
```

出现：

```
shell command timed out
```

但：

直接在宿主 Windows PowerShell：

```powershell
git --version
```

正常。

同时：

Linux WSL：

```bash
wsl git --version
```

正常。

---

# 1. 初步结论

## 结论：

**高概率不是 Git for Windows 安装问题。**

更可能是：

> OpenSeek 当前 Windows shell executor / sandbox / subprocess supervisor 与 Git for Windows 的进程模型不兼容。

---

# 2. 依据分析

## 2.1 Git for Windows 目录结构正常

Git for Windows 默认：

```
Git/
├── cmd/
│   └── git.exe
├── bin/
│   └── git.exe
├── mingw64/
│   └── bin/
│       └── git.exe
└── usr/
```

其中：

```
mingw64/bin/git.exe
```

不是额外安装的 mingw 覆盖。

而是 Git for Windows 自带运行环境。

因此：

排除：

* Git 安装错误
* mingw 冲突
* PATH 错误

---

# 3. OpenSeek 架构相关风险点

根据项目调研：

OpenSeek shell 工具不是简单执行：

```
cmd.exe
 |
 git.exe
```

而是：

```
Agent
 |
 shell tool
 |
 shell parser
 |
 sandbox policy
 |
 process supervisor
 |
 CreateProcess
 |
 git.exe
```

调研指出：

`shell` 工具包含：

* 自定义 shell 解析器
* 信任分类
* sandbox-exec
* command policy
* timeout 管理

并且：

> shell 模块包含 5639 行 sandbox 实现。
>

因此问题应优先定位 shell/process 层。

---

# 4. 为什么 Git for Windows 容易触发问题？

Git for Windows 不是单纯 Win32 exe。

执行：

```
git.exe
```

可能涉及：

```
git.exe
 |
 +-- mingw runtime
 |
 +-- git helper
 |
 +-- ssh.exe
 |
 +-- credential helper
 |
 +-- git-remote-https.exe
```

尤其 clone/fetch：

```
git
 |
 git-remote-https
 |
 curl/OpenSSL
```

或者：

```
git
 |
 ssh
```

会产生子进程。

---

如果 sandbox：

只管理：

```
git.exe
```

但是没有正确管理：

```
git.exe
  |
 child processes
```

可能出现：

* stdout pipe 未关闭
* stderr pipe 阻塞
* parent 等待 child
* timeout watchdog 误判

---

# 5. 高概率故障点

---

# H1：Windows 子进程 stdout/stderr pipe 死锁

## 概率：★★★★★

OpenSeek shell_exec 有：

* stdout 捕获
* stderr 捕获
* watchdog

调研指出：

`shell_exec`：

> 进程监督，双阈值 watchdog，内存优先 + spill 文件。



风险：

Windows:

```
CreateProcess
 |
 stdin pipe
 stdout pipe
 stderr pipe
```

和 Linux 行为不同。

如果：

* 子进程继承错误 handle
* pipe 没有异步 drain
* EOF 判断错误

会造成：

```
process running
but no output
parent waiting
timeout
```

---

## 排查

加入测试：

```powershell
cmd /c echo hello
```

如果：

```
hello
```

立即返回

继续：

```powershell
powershell -c "Write-Output hello"
```

继续：

```powershell
git --version
```

比较差异。

---

# H2：Process Job Object 杀进程逻辑异常

## 概率：★★★★★

OpenSeek 有：

* timeout
* cancel
* detach
* kill

调研：

shell：

> timeout 120s detach / 600s kill



Windows 推荐：

```
Job Object
```

管理子进程树。

风险：

错误使用：

```
AssignProcessToJobObject
```

导致：

* child process 创建失败
* child 被限制
* process 不退出

---

## 排查

记录：

Windows:

```
ProcessId
ParentProcessId
ChildProcessId
```

执行：

```
git --version
```

观察：

是否产生：

```
git.exe
 |
 git.exe?
```

---

# H3：环境变量被 sandbox 修改

## 概率：★★★★☆

Git for Windows 依赖：

```
HOME
USERPROFILE
PATH
SYSTEMROOT
TEMP
TMP
```

如果 sandbox env 白名单：

可能丢失。

调研显示：

git 子任务存在：

> 环境白名单只传 PATH/HOME，丢弃可能带恶意的 GIT_DIR 等。



风险：

Windows 下：

```
HOME
```

缺失可能影响：

```
.gitconfig
.ssh
credential helper
```

---

## 排查

sandbox 中执行：

```powershell
set
```

检查：

```
HOME
USERPROFILE
PATH
SYSTEMROOT
```

---

# H4：Shell backend 默认 Unix 假设

## 概率：★★★★☆

调研指出：

Windows 平台存在缺口：

> 无 pwsh → powershell.exe → cmd.exe 回退链。



说明：

shell executor 设计偏 Unix。

可能：

默认：

```
/bin/sh
bash
```

而 Windows：

```
pwsh
cmd
powershell
```

处理不足。

---

# 7. 修复建议

---

# 修复方案 A（推荐）

## Windows shell 使用原生 backend

不要：

```
自定义 shell parser
 |
 bash 风格执行
```

改：

```
Windows:
    pwsh.exe
        fallback powershell.exe
        fallback cmd.exe

Linux:
    bash/sh
```

---

# 修复方案 B

## 增强 Windows subprocess supervisor

必须保证：

### 1. stdout/stderr 异步 drain

不要：

```
wait process
then read output
```

应该：

```
spawn

同时:

read stdout
read stderr

await process exit
```

---

### 2. 管理整个 process tree

不要：

```
kill git.exe
```

应该：

```
kill job object
```

---

### 3. 明确关闭 inherited handles

Windows:

CreateProcess:

检查：

```
bInheritHandles
STARTF_USESTDHANDLES
```

---

# 修复方案 C

## 增加 Git for Windows 专项兼容测试

CI 增加：

Windows:

```
git --version

git init

git status

git clone local_repo
```

通过 OpenSeek shell executor 执行。

---

# 8. 不建议的修复

## ❌ 不建议：

重新安装 Git

原因：

当前证据：

* 多个 git.exe 均失败
* WSL Git 正常
* 宿主 Git 正常

问题不在 Git。

---

## ❌ 不建议：

替换为纯 Git binary

原因：

Git for Windows 已经是 Windows 标准方案。

---

# 9. 最终判断

当前最高概率链路：

```
OpenSeek shell tool
        |
        |
Windows subprocess supervisor
        |
        |
Git for Windows
        |
        |
MSYS2/MinGW runtime
```

其中：

**OpenSeek 的 Windows process/sandbox 实现缺少对 Git for Windows 这类复杂 Win32 子进程程序的兼容处理。**

优先检查：

1. `shell_exec` 的 Windows spawn 实现
2. stdout/stderr pipe 生命周期
3. process tree kill/job object
4. Windows shell backend fallback
5. env 注入逻辑

而不是 Git 安装。
