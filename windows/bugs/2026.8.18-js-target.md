# `moon test --target js` 编译报错记录

> 记录于 2026.8.18，基于 `fix/compatible/windows` 分支。

## 现象

在项目根目录执行 `moon test --target js` 时，出现大量 `Error [4139]`：

```
Error: [4139]
  ╰─ This expression has type (@moonbit-community/rabbita/cmd.Cmd, Model),
     its value cannot be implicitly ignored
     (hint: use `ignore(...)` or `let _ = ...` to explicitly ignore it).
```

## 根因

### 错误类型：Error [4139]

这是 MoonBit JS 编译器特有的错误：当函数返回 `(Cmd, Model)` 元组但调用方未使用该返回值时触发。JS 目标比 wasm/native 目标更严格地检查未使用的返回值。

### 错误位置

所有报错均来自 `desktop/frontend/update.mbt`，分布在以下行号范围：

- `update.mbt:223`
- `update.mbt:765`
- `update.mbt:1006`
- `update.mbt:1702`
- `update.mbt:2508-2648`（大量连续错误）

### 与本次改动的相关性

**无关。** 本次改动涉及的行号：
- `update.mbt:3393-3428`（`ProjectPickerLoaded` 处理逻辑）
- `view.mbt:2555-2658`（`picker_breadcrumbs` 函数）

报错行号均不在本次改动范围内，属**预存在问题**。

### 其他可能原因

`moon test --target js` 在编译 `desktop/` 包时也会编译其依赖 `desktop/lepus` 子模块。该子模块存在大量 dirty 的 `.mbti` 文件（`moon info` 运行导致），可能间接影响 JS 目标编译。

## 错误计数

```
Error [4139]: 约 40+ 处
```

## 临时规避

- 使用 `moon test`（默认 wasm 目标）或 `moon test --target native` 运行测试
- JS 目标目前不是 CI 流程的一部分，不影响日常开发
