# OpenSeek 调研报告 10：评测与测试体系

> 范围：`eval/`、`testkit/`、`viz/`、`inspect/`、`cmd/viz_app/`、`tests/`、`docs/`
> 关联：`agent-improvement-guide.md`、`improvement.md`、`todo.md`、`shrink_package.md`

## 1. 评测体系总览（`eval/`）

```
eval/report              通用报告原语（markdown/html/json 三格式）
eval/tool_harness        确定性工具冒烟（host 侧直发 execute_tool_call）
eval/file_edit           真实 agent 文件编辑评测（spawn openseek run）
eval/prompt_task         真实 agent prompt 评测（workspaces + manifest 重放分析）
eval/session_analyzer    通用会话评分器
eval/bgjobs_capability   后台任务能力评测（live）
eval/swe_agi             vendored SWE-AGI 任务集
```

### 1.1 `eval/report`（454 行）

`Metric{name,value}`（值预渲染成显示文本）、`ReportRow`、`Report`；`markdown()`/`html()`（约 120 行内联 CSS）/`to_json()`（含预计算 `successes`）；`write_files` 写 `report.{json,md,html}`；`short_cell` 截断 96 字符，markdown 表格转义 `|`。

### 1.2 `eval/tool_harness`（369 行）

- **确定性**宿主侧 harness：构造与 agent 同形的 `Tools` 注册表（read/write/edit/multi_edit/shell/plan/finish 七用例），用 `@deepseek.ToolCall` 包装参数后经 `@agent_tool.execute_tool_call` 分发，`@vfs.FileSystem` 布置 fixture 并 `mismatch_on_disk` 校验；
- `tool_definitions` 显式 `ignore(runtime)`/`ignore(scope)`（:38-39）；
- **不足**：断言硬编码工具输出措辞（如 `"ok: applied 2 edit(s)"`，harness.mbt:180），工具文案一变即脆。

### 1.3 `eval/file_edit`（harness 538 + report 123 + cases 212）

- 真实 agent：`run_trial` 在暂存 workspace 内 `moon run --target native <repo>/cmd/openseek -- run --max-steps N --model M <task>`，环境注入 `OPENSEEK_MODEL/MAX_STEPS`，`OPENSEEK_GLOBAL_SKILLS_DIR` 指向不存在的目录（隔离开发者技能）；
- `evaluate_trial` 三重判据：期望文件树 + `unchanged_files` 逐字节比对、`moon check` 验证命令、日志分析（JSONL 事件或 legacy 文本双格式）；finish 必须含标记 `file-edit-eval:<id>`；
- 5 个用例（exact_replace 等）；`TrialResult` 记录 20+ 项度量；`min_successes` 阈值决定 pass。

### 1.4 `eval/prompt_task`（suite 906 + analyzer 624 + report 366 + harness 204 + manifest 338）

- **两阶段**：`run_experiments` 只写产物（workspaces、logs、session jsonl、`run_manifest.json`）；`analyze_run` 重放 manifest，用 `ValidationProbeSpec`（支持 stdin/写文件/期望退出码/输出包含/stdout 必须是 JSON）在**最终 workspace** 独立验证，再用 `@session_log.parse_events` + `@session_analyzer` 分析会话；
- `suite.mbt`：JSON 定义 model×problem×repeat 矩阵、combo 子目录、`SuiteManifest` 持久化与 `analyze_suite` 重分析（含路径搬迁逻辑）；
- **不足**：`contains_expected_text` 硬编码 `needle=="duplicate"` 时也匹配 `"Duplicate"`（analyzer.mbt:599-602）；`EvalResult` 中 `argparse_mentions`/`from_str_mentions`/`c_ffi_mentions` 等约 20 个 API-mention 计数（analyzer.mbt:364-388）明显过拟合 TOML 时代任务。

### 1.5 `eval/session_analyzer`（225 行）

- 通用会话评分：统计 steps/tool_results/tool_errors/shell_uses/shell_failures/runtime_notices；
- **finish 归因**用 sticky 标志 `previous_finish_tool`（:124，finish 后同批 skip notes 不误判）；
- `ContextYieldAnswerPrefix` 结尾的 `Terminal(Finished)` 不算成功；
- `transcript_text` 排除 User/Summary 防任务文本污染计数。

### 1.6 其余

- `bgjobs_capability`（249 行）：live 能力评测，spawn `openseek serve`（环境只保留 PATH/HOME/TMPDIR/DEEPSEEK），S1 重叠/S2 fire-and-forget 两场景测模型**自发**使用后台任务，记分卡仅信息性；
- `swe_agi`：vendored 任务（10 pub/88 priv 测试），`openseek run --dir --concurrency N` 拷贝运行，README 坦承 priv 测试可见这一局限；
- `internal/runner`（信号量并发 + 输出目录布局）、`internal/metrics`；`prompts/`（6 个 prompt 变体）、`prompt_tasks/`（8 个任务）、`prompt_reports/`（4 份 A/B 报告，含 token/cache 表）。

## 2. `testkit/filesystem` — JSON 虚拟文件系统

```
pub(all) struct FileSystem(Json)    // 扁平 JSON：键=相对路径、值=文本
from_pairs / validate_relative_path（拒绝绝对路径、..、反斜杠、空组件，:153-171）
write_to 物化到磁盘 / mismatch_on_disk 返回首个差异描述（字符串而非 Bool）
with_tmpdir 异常路径也清理
outline.mbt 的 dir_outline：面向 prompt 的目录树；sanitize_name（:56-68）
  把控制字符（换行！）替换为 ? 并截断 64 字符——防目录名注入 prompt
```

亮点：`sanitize_name` 防 prompt 注入；不足：`mismatch_on_disk` 忽略未列出的多余文件（README 声明为有意）；注释拼写错误 "sallow"（:133）。

## 3. 可视化（`viz/`、`inspect/`、`cmd/viz_app/`）

### 3.1 viz（view.mbt 2,284 行纯函数渲染 + parse.mbt 19 行转发）

- `render_session(session, mode, subrun_children?)`，`ViewMode = RawLog | ModelView`（model view 与 `Session::chat_messages` 投影一致）；
- `group_turns` 以 `Terminal` 事件切轮次（:101-117，mid-turn steering 留在同轮）；
- plan 调用 diff 基线（`plan_baselines` :606，失败调用既不当基线也不成为基线）；
- 子 agent 转录通过解析工具 brief 文本 `"explore sr-N (…)"`（`subrun_child_id` :2151-2167）识别，内嵌渲染用全局 `anchor_namespace : Ref[String]`（:2235）避免 DOM id 冲突；
- `step_scrubber` 失败段着色；`viz_test.mbt`（1,420 行）用 `@rabbita.render_to_string` 做无头快照测试。

### 3.2 inspect（main.mbt 1,354 行，只读 HTTP 服务器）

- `Reply` 先完整计算再单次发送（:221-271，规避库的二次 `send_response` panic）；
- 路由：`/`、`/viz_app.js`（从 `_build` 定位 bundle）、`/api/sessions`（跨 roots 发现 `openseek_session-*.jsonl`，跳过 `.git`/`node_modules`/`.mooncakes`/`_build`）、`/api/sessions/<key>`（`{found, events, events_bytes}` 信封——前端 http 客户端把所有完成响应当成功，404 无法表达缺席）、原始文件端点；
- `--export` 模式冻结会话为自包含 HTML；`local_lan_ip` 用 UDP connect 探测（不发包）；session id 有 `valid_session_id` 校验。

### 3.3 cmd/viz_app（app.mbt 2,223 行 TEA 前端）

- `Msg` 16 个变体，fetch 结果带 session id 防乱序覆盖；`fetch_text` 先查 `window.__OPENSEEK_DATA__`（导出文件自足）；URL hash 保存 `s=`/`v=`/`seq=`；快捷键 n/p/u；拖放纯客户端渲染。

## 6. 跨层观察

1. **评测分层清晰**：确定性 harness（快、无模型）→ 真实 agent 评测（慢、有模型）→ live 能力评测（spawn 真引擎测自发行为）→ 真 API 冒烟（门控）→ cram（离线契约）——每一层有不同的成本/保真度权衡；
2. **可重放性设计**：`run_manifest.json` + 独立验证探针 + 会话 jsonl 持久化，让分析阶段与运行阶段解耦（模型费用花一次、分析可反复）；
3. 不足：分析器过拟合历史任务（TOML 计数）、断言硬编码工具措辞、file_edit 与 prompt_task 重复实现 spawn/env 逻辑、viz 的 DOM id 全局 Ref 依赖单线程假设；
4. 文档驱动开发是项目特色：改进决策（如输出截断、bounded read）都有 eval 数据背书，"以评测驱动工具改进"形成了正反馈闭环。
