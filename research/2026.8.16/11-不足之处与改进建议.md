# OpenSeek 调研报告 11：不足之处与改进建议

> 本报告汇总前 10 份报告中的全部问题，按**严重程度**（高/中/低）与**改进 ROI** 分级。
> 标注 🎯 的条目与项目自有的 `agent-improvement-guide.md`/`todo.md` 方向一致或可直接并入。

## 一、高风险问题（建议优先处理）

### H1. 密钥泄露通道：错误文本回显响应体

- **位置**：`deepseek/client/client.mbt:225`
- **问题**：`chat_attempt` 的失败错误文本包含**完整响应体**。若 API 网关/代理配置错误（如把请求头回显进响应），`Authorization` 头会随错误文本进入日志与事件流。
- **建议**：截断错误文本（如 2KB）+ 剥离疑似 Authorization 内容；对 MCP 的 `headers` 透传同样做脱敏告警（见 M4）。

### H2. 会话投影 O(n²)

- **位置**：`agent_session/projection.mbt:145-152`
- **问题**：`chat_messages` 双重嵌套扫描（每事件全量找 summary 覆盖）。长会话（数千事件）× 每 step 一次投影，是明确的性能债务。
- **建议**：投影时维护 summary 区间索引（游标或排序区间表），把投影降到 O(n)；同时给长会话加基准测试防回归。

### H3. shell 安全边界"退化即裸执行"

- **位置**：`agent_tool/shell/sandbox.mbt`（5,639 行）、`command_policy.mbt:18-27`
- **问题**：复杂 shell 语法解析失败时静态守卫**退化为裸执行**——这是文档自承的安全边界缺口；此外无进程组 kill（daemon 子孙存活）、`run_moonbit` 的逃逸检测只是子串扫描。
- **建议**：① 解析失败改为"默认拒绝 + 显式授权列表"（fail-closed）；② shell 工具实现进程组 kill（或至少文档化 + 测试覆盖 daemon 场景）；③ `run_moonbit` 尽快落到 wasm 后端或提升为真实边界。
- **注意**：修改安全策略会改变工具行为，需同步更新 `eval/tool_harness` 与 cram 测试。

### H4. JSON 解码浮点截断的系统性不一致

- **位置**：`deepseek/json_decode.mbt:21-25`、`agent_session/json.mbt:39` vs `protocol/parse.mbt:299-304`
- **问题**：两个 token 计数解码器对 `1.5` 一个截断、一个拒绝。token 计数是上下文压缩守卫的输入，截断会"伪造"预算。
- **建议**：统一为严格解码（拒绝小数或 `Number` 与整数精确比较）；为压缩触发边界加测试。

## 二、中风险问题（结构性 / 正确性边缘）

### M1. 巨型单体文件（可维护性）

| 文件 | 行数 | 内容 |
| --- | --- | --- |
| `agent_tool/shell/sandbox.mbt` | 5,639 | shell 静态分析 + 策略 |
| `cmd/tui/loop.mbt` | 2,142 | TUI 消息循环 |
| `cmd/openseek/main.mbt` | 2,058 | CLI 入口 + run 模式 |
| `agent/turn_loop.mbt` | 1,296 | agent step 状态机 |
| `cmd/openseek/serve.mbt` | 1,230 | serve 状态机 |
| `viz/view.mbt` | 2,284 | 会话渲染 |

- **建议**：`turn_loop.mbt` 按（goal/steer/ceiling/tool 批）拆分子状态机模块；`view.mbt` 按渲染区拆分。注意 `moon ide analyze` 辅助接口收缩（见 `shrink_package.md` 方法论）。

### M2. 跨包重复样板（DRY 缺口）

1. **转义清洗三份拷贝**：`cmd/openseek/main.mbt:918`（compact_prompt_label）、`mcp.mbt:151`（terminal_safe_line）、`cmd/tui/internal/event/decode.mbt:147`（mcp_safe）——应提取到 `internal/` 共享；
2. **子代理 validate 样板**：`agent_worker/types.mbt` 与 `agent_explore/types.mbt` 的 `parse_validated` 几乎复制粘贴——可模板化；
3. **deadline 常量三处分散**：explore 600s / worker 2700s / gate 900s——集中到一处导出；
4. **severity 校验双处定义**：`agent_review/exports.mbt:39` 与 `submit.mbt:75`（JSON Schema enum）——单一事实源 + 一致性测试。

### M3. 平台缺口

- `provision.mbt:281` 的 `copy_mooncakes` shell 出 `cp -R`——Windows 静默失败（仅日志）；
- `shell/Doc.md` 自陈：无 pwsh→powershell.exe→cmd.exe 回退链；
- `self_executable()`（subrun.mbt:336）与 TUI tcc 调试路径（rspfile 重新进入）不对称——调试路径下子进程 spawn 失败；
- **建议**：至少把 `cp -R` 换成 `@fs`/进程 API 并加 Windows 测试门；给调试路径写一个失败测试。

### M4. MCP 配置与资源问题

- `mcp.json` 的 `headers`（含 Authorization）原样透传无告警；HTTP URL 无 scheme 校验；
- 成功服务器的连接在 scope 结束前从不主动关闭——长会话累积进程/连接；
- stdio `process.cancel()` 只杀直接子进程，`npx` 类 fork 型启动器遗留孙进程；
- `tools.mbt`"按配置顺序分组"依赖 Map 迭代序——**先验证 MoonBit Map 迭代序语义**，若非插入序则改为显式数组；
- `list_tools` 分页无迭代上限（有外层超时兜底，可接受但应记录）。

### M5. TUI 输入/键盘层零测试

- `tui/ui.mbt`、`tui/input.mbt`、`tui/terminal.mbt` 无单元测试；`completion.mbt`（627 行）仅 65 行测试——键盘处理恰是回归重灾区。
- **建议**：把纯逻辑（键序列→动作映射、completion 候选生成）与终端 I/O 分离后补测试。

### M6. CLI 语义不一致

- `review.mbt:25` 硬编码 `V4Pro`，`--model` 被静默忽略；
- `default_review_max_steps=120` 被 CLI 覆盖为 unbounded（review.mbt:63），两处默认不一致；
- `retry_attempts=0` 时 `max_retry=-1` 语义未文档化；
- 🎯 与 `agent-improvement-guide.md` 的"语义 CLI 验证"优先级 1 完全对齐。

## 三、低风险问题（体验 / 理论边界 / 整洁度）

### L1. 已知行为缺陷（文档自承）

- **TUI command context fire-and-forget**（engine_client.mbt:358-379）：引擎崩溃时 `!` 命令输出静默丢失；
- `engine_command_launchable` 无超时（main.mbt:407）：`--help` 探测挂起会卡死 TUI 启动；
- `notify` 在 outbox 关闭时静默丢消息（jsonrpc）；
- 未知 `steer kind` 默认当 Prompt（decode.mbt:29-34）；
- goal clear 无 goal 时也发 tombstone（产生无意义事件）。

### L2. 性能细节

- `serve.mbt` `pending.remove(0)` O(n)（队列小，可忽略）；
- `parse_session_file` 无行数上限、全量 split 解码；
- `pending_goal_acks.search(goal)` 线性扫描；
- `chat_messages` 每次调用全量重建——若成为热点可增量缓存（依赖 Session 不可变性，安全）。

### L3. 资源清理

- `write_text_atomic` rename 失败残留 `.tmp` 文件；
- streamhttp close 时 best-effort DELETE 可能被组 teardown 取消（会话靠服务端过期）。

### L4. 死代码与过拟合

- `prompt/generated_base_prompt.mbt` 1,316 行未选中死代码——删除或启用；
- `eval/prompt_task/analyzer.mbt` 约 20 个 API-mention 计数过拟合 TOML 时代任务；
- `contains_expected_text` 的 `needle=="duplicate"` 大小写 hack（analyzer.mbt:599-602）；
- `tool_harness` 断言硬编码工具输出措辞（`"ok: applied 2 edit(s)"`）——工具文案一变即脆；
- `Ui::redraw` 缺 viewport 时 `abort()`——可改为错误返回；
- config 非法参数（负 esc_timeout）静默回落默认值无警告。

### L5. 测试盲区

- `tui` 框架层（见 M5）；`agent_tool/shell` 家族几乎无单元测试；
- `lifecycle_test.mbt` 对 integrate"foreign merge 保护"路径覆盖不足（`merge --abort` 后状态回写无断言）；
- 转换：`deepseek` 的 `reasoning_content` 静默丢弃行为有测试背书但属易误用 API——建议改显式报错或文档高亮；
- `Usage::from_json` 与 protocol `int()` 的严格度不一致无测试钉死。

## 四、值得肯定的设计（防回归清单）

以下设计是项目的核心资产，任何重构都应保持其行为：

1. **双轨架构**：live 事件流可丢、durable session 是唯一真相；
2. **上下文预算三层防护**（70%/80% + 运行中检查 + 16K checkpoint 预留）与控制工具抢救；
3. **steer 无损队列**与事件有损总线的分离；
4. **"先落盘后镜像"**、**store 指纹快路径 + 原子重写 + 撕裂尾部容错**；
5. **execute_tool_call 统一错误边界**（异常→可恢复错误、取消→re-raise）；
6. **文件编辑纪律**（FileStateMap + digest + 语法门 + 自动回滚 + 只删自建）；
7. **subtask 证据式 git**（write-tree 钉快照、postcondition 分类、`-z` 解析器）；
8. **子代理报告"建议性 + 父侧 git 校验"**双层信任；
9. **serve 单消费者队列** + **goal promotion 序号防超车**；
10. **协议严格解码**（required 字段 + 拒绝小数 + 唯一编码器）。

## 五、建议的行动顺序

按 ROI 排序（结合 `agent-improvement-guide.md` 的优先级）：

1. **H1 密钥泄露**（安全，改动小）：截断错误文本 + 脱敏测试；
2. **H4 浮点截断统一**（正确性，改动小）：统一解码策略 + 压缩触发边界测试；
3. **H2 投影 O(n²)**（性能，改动中）：区间索引 + 基准测试；
4. **M2 重复样板提取**（维护性，改动小）：转义清洗三合一、deadline 集中；
5. **M6 CLI 语义一致**（🎯 与 roadmap 优先级 1 重合）：`--model` 生效、默认值单一化；
6. **H3 fail-closed**（安全，改动大）：需同步 eval 与 cram 测试，谨慎排期；
7. **M1 单体拆分**（维护性，改动大）：配合 `moon ide analyze` 接口收缩逐步进行；
8. **M5 键盘层测试**（质量，改动中）：纯逻辑与 I/O 分离后补测试。
