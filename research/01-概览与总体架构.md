# OpenSeek 调研报告 01：项目概览与总体架构

> 调研日期：2026-08-10
> 调研方式：通读 README、docs/architecture.md、moon.work/moon.mod 及各包源码
> 代码规模：全仓约 95,000 行 MoonBit（337 个 .mbt 文件），不含 desktop/ 与 editor/

## 1. 项目定位

OpenSeek 是一个以 **MoonBit** 编写的、面向 **DeepSeek（及 Kimi）大模型**的编码 Agent 基础库与 CLI 工具。其核心设计哲学在 `docs/architecture.md` 中明确：

- **Session 是唯一记忆**：模型上下文只通过持久化会话（durable session）携带，进程退出后对话可恢复；
- **事件 append-only**：所有对话历史是不可变的事件日志，工具执行、摘要压缩都以追加方式落盘；
- **工具即数据**：工具定义、调用、结果都是结构化数据，模型通过原生 tool-call 驱动一切行为；
- **请求编码与网络解耦**：纯数据包（`deepseek`）可在无网络环境测试。

项目同时携带一个大型 monorepo：`moon.work` 把 OpenSeek 与桌面应用（`desktop/`，CEF + lepus 子模块）和 `moonbitlang/editor`（`editor/`，可复用只读编辑器）放在同一 workspace 中开发。

## 3. 关键架构决策

### 3.1 双轨架构：live 事件流 + durable session 日志

引擎（`serve` 模式）在 stdout 上输出 JSONL 事件流（`protocol/`，约 40 个 `Event` 变体，经 `@xlog` 管道写出），同时把真实会话状态持久化到 `.openseek/sessions/<id>/openseek_session-<id>.jsonl`。二者由"**先落盘后镜像**"（`agent/turn_loop.mbt:304-313`）维持一致：

- TUI、桌面前端只消费 live 事件流（可丢弃、可重连）；
- 引擎重启/恢复只信 session 文件；
- `viz` 完全离线渲染 session 文件。

### 3.2 上下文预算（auto-compact）体系

`agent/auto_compact.mbt` 实现三层防护：

- **70% 软 ceiling**：本批次仍执行，checkpoint 摘要生成后优雅退出回合；
- **80% 硬 ceiling**：批次不启动，skip-close 后 yield；
- **每次调用前运行中预算检查**（`next_call_fits`）：实际已记录尺寸 + 最坏结果 + 16,384 token checkpoint 预留。

`salvage_control_calls_at_ceiling`（`turn_loop.mbt:854`）保证 `finish`/`goal` 控制工具在 ceiling 下仍被执行——这是全库最精巧的设计之一。

### 3.3 结构化并发

- `jsonrpc`：reader/writer 双常驻任务 + 无锁 pending Map（协作式 async 保证）；
- `serve`：所有事件 funnel 进单一有序队列 + 单消费者泵（`ServeStep` 五态），消除命令/回合生命周期竞态；
- `agent_subrun`：子进程 EOF = 优雅取消信号，deadline + 5s grace 窗口；
- `internal/subtask`：进程内 mutex 事务 + git 证据式 capture（write-tree 钉住不可变快照）。

### 3.4 信任边界分层

模型/工具输出不可信 → 层层设防：工具结果截断（12K/50K/60K）、shell 静态分析（sandbox.mbt 5,639 行）、write 拒绝覆盖源文件 + realpath 双检查、remove 只删有 digest 证明的自建文件、子代理报告父侧 re-validate、`terminal_safe_line` 防终端转义注入、`git_run` 环境白名单。

## 4. 工程实践特点

- **文档即代码**：每个包有 README.mbt.md；提示词由 `dev_build(md_to_mbt_string)` 从 Markdown 生成（`generated_*.mbt`）；CLI 行为由 cram 测试背书；
- **eval 驱动开发**：`todo.md`、`improvement.md`、`agent-improvement-guide.md` 记录了完整的 A/B 评测历史（如"文档引导使 pro 模型 1/5 → 5/5"）；
- **dogfood 注释文化**：源码注释大量记录真实事故教训（ccomp-run10、sr-2、Codex review 对比）；
- **测试分层**：单元/白盒/黑盒测试（约 40,000 行测试代码）+ mock TCP 服务器 + 真 API 冒烟（环境变量门控）+ cram 离线测试 + live 测试。

## 5. 总体评价

这是一个工程质量极高的代码库：模块边界清晰（纯层→传输层→编排层→入口层），错误分类细致（可重试/不可重试、可恢复/不可恢复），边界处理（超时/截断/幂等/取消）近乎苛刻。主要债务集中在：巨型单文件（`sandbox.mbt` 5,639 行、`turn_loop.mbt` 1,296 行、`view.mbt` 2,284 行）、跨包重复样板（转义清洗三份拷贝、子代理 validate 样板、deadline 常量三处分散）、若干平台缺口（Windows 的 `cp -R`/pwsh 回退）、以及文档化的"best-effort"安全边界。
