# OpenSeek 调研报告 05：工具系统与安全边界

> 范围：`agent_tool/`（约 9,000 生产行 + 6,000 测试行）、`agent_skill/`、`prompt/`
> 子包：bgjobs, edit, finish, goal, multi_edit, plan, read, remove, run_moonbit, shell, shell_exec, shell_output, shell_stop, write, write_scope, file_state

## 1. 框架层（`agent_tool.mbt`，586 行）

```
pub struct AgentToolDefinition { name; description; schema: JsonSchema
  execute: ToolExecutor; control: Bool; concurrent_safe: Bool }
pub(all) enum ToolExecutor { Async(async (Json) -> ToolAction) | Sync((Json) -> ToolAction) }
pub enum ToolAction { Respond(ToolOutput) | Control(AgentControl) }   // Finish(String) | Abort(String)
pub struct Tools { priv by_name: Map[String, AgentToolDefinition] }   // 重名 raise
pub async fn execute_tool_call(call, tools) -> ToolAction             // :291 统一错误边界
```

### 1.1 设计决策

- **错误边界统一**：`execute_tool_call` 把工具异常包装为 `Respond(is_error=true)`（模型可恢复），**取消除外** re-raise 使 turn 可中断（:297-300）；
- `control`/`concurrent_safe` 是**仅内置特权**（:51-68 文档化，MCP 构造点有测试钉死）——外部工具（MCP）永远拿不到控制权与并发权；
- 工具返回 `ToolAction` 而非裸数据，使"控制流"与"数据流"类型化分离。

## 3. 编辑纪律（文件工具链的核心理念）

文件工具链围绕一条主线：**模型对文件系统的操作必须是可审计、可回滚、不破坏工程语义的**。

1. **来源追踪**：`FileStateMap` 记录每个文件是 agent 自建（Created）还是既有（Preexisting）；digest 证明内容未被篡改；
2. **语法门**：write 用 `moonc syncheck` 预解析，multi_edit 用 `moon check --output-json` 错误计数自动回滚（超过阈值即 revert 整批）——把"编译器就是 ground truth"落到了工具层；
3. **防写穿**：CreateNew vs CreateOrTruncate 区分防悬空 symlink 攻击；
4. **只删自建**：remove 只删有 digest 证明的 agent 自建文件，既有文件只能 edit 不能 remove（防止模型"删库"）。

## 4. shell 安全体系（`sandbox.mbt` 5,639 行）

这是全库最大的单文件，承载：

- **自定义 shell 解析器**：lexer/parser/query，对模型输入做结构化理解而非字符串黑名单；
- **信任分类**：`source_write_mode_for_parse` 输出 SourceReadOnly/TrustedSourceWrite，决定命令可写性；
- **read_only 模式**（review_guard.mbt:49）：阻断 `moon fmt`/`moon info`/`moon test --update` 等写操作；
- **命令策略**：阻断 `moon_cmd`/`sed -i` 等危险模式；
- **git 策略**（673 行附近）：检测 `git` 写对象存储的操作。

### 已知局限（多为文档自承）

- 复杂 shell 语法解析失败时静态守卫**退化为裸执行**（command_policy.mbt:18-27 自述）；
- 无进程组 kill，daemon 子孙进程可存活；
- `run_moonbit` 的"安全"是子串扫描，非真实边界（wasm 后端未落地前文档承认）；
- Windows 无 pwsh→powershell.exe→cmd.exe 回退链（shell/Doc.md 自陈）。

## 5. `agent_skill/` — 技能系统（约 200 行）

```
pub async fn discover_skills(dir: String) -> Array[Skill]        // :68 两种布局 + 按名排序
pub fn merge_skills(base, overrides~) -> Array[Skill]            // :117 override 同名 shadow base
pub fn skills_prompt_section(skills) -> String?                  // :136 只列元数据
```

- **发现**：`<dir>/<name>.md` 与 `<dir>/<name>/SKILL.md` 两种布局；
- **frontmatter**：简单行解析（`---` 块内 `name:`/`description:`），缺省回退文件名 stem；
- **合并语义**：workspace 技能 shadow 同名 global 技能；
- **设计决策**：正文不进 prompt，只在列表给路径（"pre-approved reads"）——技能由模型按需读取，省上下文；
- **不足**：`parse_frontmatter` 用 `split_once(":")`，含冒号的 description 被截断、无多行 YAML；静默 fallback 掩盖错误；无排除目录机制。

## 6. `prompt/` — 系统提示词

- `system_prompt_for_model(_model)` **忽略模型参数**，全部返回同一默认提示词（prompt.mbt:7）；
- 提示词由 dev_build 规则 `md_to_mbt_string` 从 `default_prompt.mbt.md` 生成（generated_default_prompt.mbt 651 行）；
- `generated_base_prompt.mbt`（1,316 行）保留但未选中——**1,316 行死代码**常驻仓库；
- 提示词质量由 `eval/prompt_task` 端到端测试背书。

## 7. 跨层观察

1. 工具系统的安全设计是"纵深防御 + 诚实声明"的范本：每层边界都标注了已知的 best-effort 缺口，而不是假装绝对安全；
2. **最大的结构性问题**：`sandbox.mbt` 5,639 行单文件、`shell_exec` 双文件 1,000 行——shell 家族占 agent_tool 一半以上行数，却几乎无单元测试（主要靠 e2e 与 eval 覆盖）；
3. 截断/预算纪律一致贯彻：read 12K、工具结果 60K、shell 输出 spill 20M、bgjobs 30min——但数值散落各处，是隐式契约；
4. 技能与 prompt 是"轻量但够用"的典型：frontmatter 解析简化是刻意的，但"含冒号截断"这类坑值得至少一个测试钉死。
