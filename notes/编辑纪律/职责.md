**“编辑纪律”主要服务于代码 Agent 修改工程文件的场景**，尤其是 MoonBit 项目里的 `.mbt` / `.mbt.md`。

# OpenSeek 编辑纪律调研：三层安全闸门

> 源码：`agent_tool/internal/auto_check/parse_gate.mbt`、`agent_tool/internal/auto_check/auto_check.mbt`、`agent_tool/internal/auto_check/moon_check.mbt`

## 闸门体系总览

OpenSeek 的编辑纪律建立在**三层安全闸门**之上，每层拦截不同级别的错误：

```
                                  语法错误    类型错误    语义错误
                                  (code 3xxx)  (code 4xxx+) (moon check)
第一层：参数验证（参数解码）          ✅          -           -
第二层：预写入语法门（syncheck）     ✅          ❌          ❌
第三层：写入后编译门（moon check）   ✅          ✅          ✅
```

## 第一层：参数验证

**范围**：write/edit/multi_edit 的参数解码阶段

- `write`：检查 `path`、`content` 必填字段，`create_only` 布尔值
- `edit`：检查 `file`、`old_string`、`new_string`，验证 `start_line`/`end_line` 范围，`replace_all_preview` 布尔值
- `multi_edit`：验证每个编辑项的 `file`、`old_string`、`new_string`，检查同一文件内编辑重叠

**机制**：参数解码失败 → 返回 `ToolAction::respond(is_error=true)`，不读磁盘、不碰文件。

## 第二层：预写入语法门（The Syntax Gate）

**共享实现**：`parse_gate.mbt` 的 `content_parse_errors()`（133-187 行）

### 架构

```
content_parse_errors(path, content):
  │
  ├─ ① gate_scratch_name(path)  → 确定临时文件名
  │    .mbt    → parse_gate.mbt
  │    .mbt.md → parse_gate.mbt.md
  │    moon.mod → moon.mod
  │    moon.pkg → moon.pkg
  │    others  → None（跳过门控）
  │
  ├─ ② @fs.tmpdir(prefix="openseek-parse-gate-")
  │
  ├─ ③ @fs.write_file("{dir}/{scratch_name}", content, CreateOrTruncate)
  │
  ├─ ④ @async.with_timeout_opt(10s, () => {
  │      @shell.collect_shell_output(
  │        "moonc syncheck -error-format json {scratch_name}",
  │        cwd=dir, max_output_chars=200000
  │      )
  │    })
  │
  ├─ ⑤ decide_parse_gate(output) → ParseGate?
  │    ├─ 词法/语法错误 → Some({errors, truncated})
  │    ├─ 退出码 0 且无错误 → Some({errors: [], truncated: false})
  │    ├─ 输出截断且无错误捕获 → None（故障开放）
  │    └─ moonc 缺失（exit 127）或输出无法解析 → None（故障开放）
  │
  └─ ⑥ noraise: cleanup temp dir
```

### 增量检查（核心）

`edit` 和 `multi_edit` 都做**增量比较**——门控关心的是**新增**了多少错误，而非绝对错误数：

```moonbit
// edit.mbt:738-743
let before_count = before.errors.length()
let introduced = gate.errors.length() - before_count
if introduced <= 0 { continue }  // 没有新增错误 → 放行
```

这意味着：
- 修复一个已有语法错误的编辑**不会被门控拒绝**
- 只有在你的编辑**引入**了新语法错误时才会被拦截
- 如果旧内容的解析被截断（`truncated`），跳过该文件的增量检查（无法可靠比较）

### 支持的文件类型

`gate_scratch_name()`（parse_gate.mbt:58-70）支持四种文件类型：

| 原始路径后缀 | scratch 文件名 | 说明 |
| --- | --- | --- |
| `.mbt` | `parse_gate.mbt` | MoonBit 源码 |
| `.mbt.md` | `parse_gate.mbt.md` | MoonBit 文档源码 |
| `moon.mod` | `moon.mod` | 模块清单 |
| `moon.pkg` | `moon.pkg` | 包清单 |

对于 symlink 跨类别（如 `link.mbt→doc.mbt.md`），`gate_paths()`（parse_gate.mbt:102-114）返回去重的两种类型，分别检查。

### 故障开放策略

当无法确定内容是否合法时，闸门**放行而非拦截**（fail-open）：

- moonc 缺失（exit 127）→ `None`，放行
- 输出截断且无错误捕获 → `None`，放行（不信任截断后的\"干净\"判断）
- 命令超时（>10s）→ `None`，放行
- 临时目录/文件创建失败 → `None`，放行

这是刻意设计：工具可用性优先于严格性——moonc 偶尔不可用不应阻止 agent 工作。

### 错误码筛选

`decide_parse_gate()`（parse_gate.mbt:196-233）只提取**词法/语法错误**（错误码 3000-3999）：

```moonbit
// parse_gate.mbt:37-40
fn is_parse_error_code(code: Int) -> Bool {
  code >= 3000 && code <= 3999
}
```

**类型错误**（错误码 ≥ 4000）不会被第二层闸门拦截——交给第三层的 `moon check`。

## 第三层：写入后编译门（The Compilation Gate）

**仅 `multi_edit` 拥有**。`edit` 的 `moon check` 只做信息性摘要，`write` 没有写入后检查（因为写的是新文件，`moon check` 前需要其他已有文件）。

### 架构

```moonbit
// multi_edit.mbt:576-651 revert_guarded_response()

async fn revert_guarded_response(writes, threshold, write_scope?, emit?):
  │
  ├─ ① before_count = from 写入前的 error count（重新测量基线）
  │    注：不使用 pre-batch 内存中的计数，因为其他进程可能已改变文件
  │
  ├─ ② @fs.write_file → 写入所有文件到磁盘
  │
  ├─ ③ after = count_errors()  # moon check --output-json
  │
  ├─ ④ introduced = after.error_count - before_count
  │
  ├─ ⑤ if introduced > threshold:
  │      ├─ write_files(writes, write => write.original_content)
  │      └─ 返回 revert_report()
  │    else:
  │      └─ 返回 success_report()
```

### `count_errors()` 实现

```moonbit
// auto_check.mbt:79-132
pub async fn count_errors(path: String) -> CheckErrors? {
  guard moon_check_cwd(path) is Some(cwd) else { return None }

  let result = @async.with_timeout_opt(30000, () => {
    @shell.collect_shell_output(
      "moon check --output-json",
      cwd, max_output_chars=400000,
    )
  })

  result.map(output => tally_diagnostics(output.text, output.output_limit_reached))
}
```

### `tally_diagnostics()` 逻辑

```moonbit
// auto_check.mbt:100-132

  // 解析每行 JSON（JSON Lines 格式）
  // 筛选 level=="error" → error_count++
  // level=="warning" → warning_count++
  // 前 RevertErrorDisplayLimit=10 个错误格式化输出
```

- 检测所有编译器诊断（语法 + 类型 + 语义）
- 错误级别：`error` 计入 error_count，`warning` 计入 warning_count（不触发回滚）

## 闸门对比矩阵

| 维度 | 第二层（syncheck） | 第三层（moon check） |
| --- | --- | --- |
| 触发时机 | **写入前** | **写入后** |
| 检查范围 | 仅词法/语法（3xxx） | 全部编译器诊断 |
| 检查方式 | 独立文件级别 | 项目级别（含依赖） |
| 超时 | 10 秒/文件 | 30 秒/项目 |
| 错误处理 | 故障开放（None = 放行） | 故障开放（None = 不回滚） |
| 工具覆盖 | write, edit, multi_edit | 仅 multi_edit |
| 反应 | 拒绝（不写入） | 回滚（重新写入原始内容） |
| 增量检查 | ✅ 仅新增错误 | ✅ 仅新增错误 |
| 输出上限 | 200,000 字符 | 400,000 字符 |

## 设计哲学

1. **分层防御**：语法错误在写入前拦截（零成本修复），编译错误在写入后检测（可回滚）
2. **故障开放优先**：不确定时放行而非阻拦——保持 agent 向前推进
3. **增量原则**：只对新增的错误负责，不惩罚已有的损坏
4. **语法≠编译**：语法门只拦 3xxx，类型错误留给第三层，避免过度拒绝（类型错误可能需要多步修改解决）
